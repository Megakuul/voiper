# SIP signaling support

This package owns account registration, SIP transports, transactions and dialogs through sipgo. It does not own audio, application configuration, UI state or vendor dialects. Callbacks can run concurrently and must return promptly; do not call `Close` inline from a callback.

Implemented:

- UDP with one shared signaling socket, TCP, and verified TLS using the established outbound connection. A private CA can be supplied through `Config.TLSConfig`. TLS does not expose a separate inbound listening service.
- REGISTER with authentication username distinct from public identity, 401/407 digest authentication, negotiated expiry, bounded 423 retry, refresh, initial transient retries and best-effort unregister on close. TLS registration refresh reconnects and advertises the actual connection endpoint. Registration resolves SRV records when the server port is omitted, using A/AAAA only when no SRV service exists; explicit ports use A/AAAA directly. A bounded candidate set supports registrar failover on transient failures and retains the successful route for account requests.
- Incoming/outgoing INVITE, ringing, SDP exchange, ACK, rejection, CANCEL, BYE, ringing-call 302 redirection, and re-INVITE through an explicit media negotiation callback. The first selected answered dialog is retained; additional forked answers are ACKed and ended with BYE using their own tags, Contact and route set. Late successful answers after cancellation receive the same cleanup during a bounded retention window. Re-INVITE responses/ACKs are retransmitted on UDP.
- INFO DTMF; blind REFER and attended REFER with Replaces. REFER acceptance is distinct from completion; validated NOTIFY progress is delivered separately as `transfer` events with `StatusCode` and `State` (`pending`, `success`, `failed`). One pending REFER per dialog is correlated with its actual CSeq and optional event id; subsequent REFERs require event ids. Final notifications received before the REFER response are held until acceptance, duplicate completions are suppressed, and missing results expire after two minutes. Unsolicited notifications and malformed sipfrag/MIME cannot complete a transfer. Incoming REFER runs an explicit transfer handler with progress/final NOTIFY. Replaces validates both established-dialog tags before asking the application to replace a call. Without a transfer handler, unsupported REFER receives 501.
- PRACK/100rel per outgoing early fork, delayed offers answered in PRACK or ACK, early/established UPDATE and negotiated session refresh/expiry. Mid-dialog digest challenges, bounded glare retries and context-aware operation serialization. Accepted UPDATE/re-INVITE Contacts refresh the target of later INFO/BYE requests without changing established routes or credential scope.
- Configurable OPTIONS keepalives and TCP/TLS flow re-registration. Contacts track the actual outbound connection after registration/reconnection, and incoming requests reuse that flow. Opt-in bounded SIP redirects reject cycles, URI header injection and SIPS downgrade, and strip credentials before forwarding.
- Digest credentials stay within the configured account authority: origin 401 challenges require the configured Server/Domain and port; proxy 407 challenges require the configured registrar route or explicit outbound proxy. A redirect to a different scheme, host or port cannot authenticate, including later dialog requests. Direct calls and REFER targets do not implicitly expand this credential scope.
- `AbortCall` cancels local call state and pending work when orderly signaling misses its deadline. It does not report a remote BYE as successful.
- Bounded UTF-8/plain text SIP MESSAGE. A successful response means accepted by the peer/server, not delivered/read by the recipient.
- Generic SUBSCRIBE refresh/unsubscribe and correlated NOTIFY delivery, suitable for presence, dialog/BLF and message-summary. Logical watch IDs survive transient recovery; replacement dialogs use fresh wire IDs/tags and reject old notifications. `RefreshSubscriptions(ctx)` schedules refresh after network recovery, honoring server retry delays. Application code interprets the bounded raw bodies. PUBLISH supports PIDF, SIP-ETag updates, granted expiry, bodyless refresh/removal and bounded Min-Expires negotiation. The application owns the serialized refresh lifetime; Voiper refreshes and withdraws its publications.
- Narrow generic extension request/response hooks. Vendor interpretation belongs outside this package.

Deliberate remaining limits:

- No complete RFC 5626 instance-ID/reg-id/flow-token negotiation. Registrar failover supports up to eight DNS destinations, a three-second DNS lookup, three-second attempts and a fifteen-second overall exchange. DNS results are refreshed on registration after at most one minute of cache reuse (`net.Resolver` does not expose TTLs). There is no NAPTR transport selection; the configured transport remains fixed. Existing dialogs keep their established routes, and ambiguous INVITE/MESSAGE transactions are never replayed. SDP/media ICE/STUN/TURN belongs to the media layer; `rport` alone does not solve all NAT cases.
- Redirect following is disabled by default; callers must opt in with `MaxRedirects` (1–5).
- `Dial`/`DialID` send an initial SDP offer. `DialDelayedID(ctx, id, target, answerOffer)` instead sends a bodyless INVITE and answers the selected final 200 offer in ACK. Its callback prepares transport/SDP, honors cancellation, and returns before waiting for media connectivity; the subsequent `connected` event has `DelayedOffer=true` and contains the accepted remote offer. It runs once for the selected final dialog. Extra forks, canceled calls and rejected offers receive a rejection answer and BYE without allocating application media. Malformed offers that cannot be parsed receive a bodyless ACK and BYE. This compatibility API does not advertise 100rel; required reliable provisional offers are canceled, and unreliable provisional SDP is ignored. Delayed incoming offers use the final 200/ACK exchange; bodyless re-INVITEs request a fresh offer from `SetOfferHandler` with a nil body and validate the ACK answer through `SetAnswerHandler` and apply it through `SetAnswerCommitHandler` before emitting `updated`.
- `DialDelayedOptionsID(ctx, id, target, DelayedOfferOptions{Prepare: ...})` also supports reliable provisional offers. `Prepare` returns `DelayedAnswer{SDP, Select}` for each fork; it may run again when that fork sends an early UPDATE. Preparation has a five-second cancellation deadline and at most sixteen candidates. The candidate context owns its lifetime: canceled for a lost/replaced fork, retained until teardown for the selected final dialog. `Select` attaches only the winning media immediately before ACK; audio waits for `connected`. A rejected replacement leaves the previous candidate intact. Final SDP cannot silently replace a previously negotiated offer; the original repeated SDP after UPDATE preserves the newest negotiated media.
- Bodyless early UPDATE is accepted for known dialogs without starting session timers before answer. Delayed early UPDATE replaces prepared candidates only after a successful response. For initial-offer calls, `SetEarlyOfferHandler` handles UPDATE for the first early dialog providing playback after reliable offer/answer completes. It must keep microphone capture closed. Other early forks cannot mutate that playback session. `connected.AnswerTo` supplies the original INVITE offer when the final answer still needs validation against it; successful early UPDATE instead preserves its latest remote offer. Initial-offer ICE/DTLS branch switching requires media support; unsupported association changes must fail explicitly. Incoming early offers in PRACK and incoming early UPDATE offers before an initial answer remain unsupported.
- `ended.TerminationReason` is `answered-elsewhere` for standardized `Reason: SIP;cause=200` on a matching initial CANCEL or validated-dialog BYE. CANCEL attribution also checks the original peer, transaction, tags, and request identity; arbitrary display text is ignored. This does not authenticate direct incoming peers.
- Fork cleanup retains transaction identity for 32 seconds after settlement, with at most 16 remote tags and 16 INVITE attempts per logical call, and 256 retained attempts per account. Responses outside these bounds are not supported; candidate preparations and early UPDATE exchanges are serialized per call.
- No authentication of direct incoming calls or verification of caller-supplied display identity. Generic peer requests must be handled within the deployment's trust boundary.
- Codec-changing re-INVITEs depend on application media support. Voiper resamples to the fixed device PCM rate without reopening devices, including during recording and conferences. Rate conversion requires SpeexDSP. `ReinviteWithOffer` generates offers and `SetAnswerCommitHandler` applies answers within the same serialized call operation; `updated` is a notification, not an instruction to asynchronously apply SDP. A rejected operation returns an error; it is not reported as completed.
- Subscription timeout, deactivation and probation recover with bounded backoff; rejected/noresource/giveup and unknown terminal reasons stop the watch. Initial Subscribe failures still return an error. Missing dialog-info versions become unknown until a full update arrives.
- Direct TLS account connections reuse the server flow and verify certificates against the configured registrar or explicit outbound proxy name, even when DNS selects another address. An explicit `TLSConfig.ServerName` overrides that identity. Direct foreign TLS destinations on this account must therefore present the configured identity. Peers requiring an independently reachable TLS listener, special client certificates or proprietary authentication need deployment-specific configuration/validation.

The loopback suite exercises UDP/TCP registration/calls, SHA-256 digest authentication, refresh/cancellation, messages, DTMF, re-INVITE, redirection, credential isolation, deadline cancellation, forked/late answers, fork-aware reliable delayed offers, early UPDATE candidate replacement and sequence retention, normalized cancellation reasons, moved-Contact targets, correlated transfer completion, outgoing delayed offer answers/rejections/cancellation, subscriptions, trusted/untrusted TLS, session timers, serialized answer commits, inbound transfer and exact Replaces matching. Independent SIPp fixtures exercise reliable provisional responses, PRACK, delayed offers and UPDATE. `pkg/media` additionally tests signaling plus synthetic media. These tests do not certify an external PBX or Swyx deployment.

Delayed-offer cleanup follows [RFC 3261 section 13.2.2.4](https://www.rfc-editor.org/rfc/rfc3261.html#section-13.2.2.4) and rejects media streams with zero ports as specified by [RFC 3264 section 6](https://www.rfc-editor.org/rfc/rfc3264.html#section-6). Reliable provisional offer/answer follows [RFC 3262](https://www.rfc-editor.org/rfc/rfc3262.html), early UPDATE follows [RFC 3311](https://www.rfc-editor.org/rfc/rfc3311.html), and answered-elsewhere attribution follows [RFC 3326](https://www.rfc-editor.org/rfc/rfc3326.html).

Registrar discovery follows [RFC 3263](https://www.rfc-editor.org/rfc/rfc3263.html); TLS discovery retains the configured identity as required by [RFC 5922](https://www.rfc-editor.org/rfc/rfc5922.html). `Config.Resolver` optionally supplies a standard Go DNS resolver for custom resolution and isolated interoperability tests.

Transfer result correlation follows [RFC 3515](https://www.rfc-editor.org/rfc/rfc3515.html), including event ids for repeated REFER within one dialog.
